# Довідник операцій

Кожна операція Git приймає context.Context. Один клієнт і відкритий
репозиторій можна використовувати одночасно для читання. Git сам блокує
змінювані refs та індекс. Для узгодженого перегляду історії отримайте повний
ID через Resolve і передайте його наступним операціям.

| Група | Операції та наслідки |
| --- | --- |
| Репозиторій | New, Version, Capabilities, Open, OpenManaged, Info, Head, IsBare, IsShallow читають стан. Init створює сховище, Clone копіює об’єкти через транспорт. |
| Посилання | Resolve, Refs, SymbolicRef, Branches, Tags і TagInfo читають імена. UpdateRef перевіряє попередній ID. CreateBranch, DeleteBranch, RenameBranch, CreateTag і DeleteTag змінюють refs. |
| Об’єкти | Log, CommitInfo, Parents, Tree, ObjectInfo, Blob, ReadFile і Blame читають історію та вміст. |
| Зміни | Diff віддає патч потоком, DiffStat повертає лічильники або ознаку бінарного файлу, ChangedFiles зберігає обидва імені перейменування. У bare потрібні дві ревізії. |
| Робоча копія | Status читає індекс і файли. Add, Remove, Restore, Checkout, Switch та Commit змінюють робочу копію, індекс або історію. Restore замінює незбережені в індексі зміни. |
| Злиття | MergeBase й IsAncestor читають граф, MergeTree записує об’єкти дерева, Merge змінює поточну гілку та робочу копію. |
| Синхронізація | Remotes, RemoteInfo, AddRemote і RemoveRemote працюють із налаштуваннями remote. Fetch, Push, LsRemote та Pull використовують транспорт. Pull допускає лише fast-forward і потребує робочої копії. |
| Конфігурація | GetConfig і ListConfig читають локальні значення. SetConfig і UnsetConfig змінюють їх. |
| Обслуговування | Fsck перевіряє об’єкти, CountObjects і Size вимірюють сховище, GC перепаковує його. Archive і BundleCreate повертають потоки, BundleVerify і BundleListHeads читають локальний бандл. |

## Ліміти та помилки

Типові ліміти клієнта — 16 паралельних процесів, 16 МіБ накопиченого виводу
та п’ять хвилин на команду. Потокові методи Blob, Diff, Archive, Blame і
BundleCreate вимагають Close. Помилка після початку читання робить частковий
результат непридатним для збереження як повний файл. Стан порожньої гілки
позначає ErrUnbornHEAD, перевищення ліміту — ErrOutputLimit. Назви шляхів
можуть містити довільні байти; для передавання невалідного UTF-8 через JSON
потрібне окреме кодування.

## Серверний режим

OpenManaged дозволяє переглядати об’єкти й посилання у bare-репозиторії
під абсолютним коренем. Ідентифікатор має складатися з простих ASCII-компонентів
і закінчуватися на .git. Сервіс контролює всю файлову структуру протягом
життя дескриптора. Режим відхиляє сторонні конфігурації, includes,
альтернативні сховища й partial clone. ОС має обмежувати доступ до диска,
мережі, пам’яті та CPU.

githttp перевіряє право читання або запису перед кожним зверненням до
репозиторію. Для push потрібні EnablePush та дозвіл на запис. Початкові
межі — вісім запитів, п’ять хвилин і 1 ГіБ в кожен бік. Встановіть також
мережеві тайм-аути й TLS. Бандл містить refs і досяжні об’єкти; для повної
резервної копії окремо збережіть конфігурацію, хуки, reflogs, недосяжні
об’єкти, LFS та дані застосунку.
